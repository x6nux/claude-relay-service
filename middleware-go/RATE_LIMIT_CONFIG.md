# Middleware-Go 账号异常限流配置

## 改动说明

已将所有账号异常情况的限流时间统一设置为 **5 分钟**。

### 之前的配置

之前根据不同的错误类型有不同的限流时间：
- 401/403 错误（认证/权限）：30 分钟
- 429 错误（限流）：1 小时  
- 5xx 错误（服务器错误）：10 分钟
- 其他错误（网络等）：5 分钟

### 现在的配置

所有异常情况统一限流 **5 分钟**：
- 401 错误（未授权）：5 分钟
- 403 错误（禁止访问）：5 分钟
- 429 错误（限流）：5 分钟
- 500/502/503/504 错误（服务器错误）：5 分钟
- 网络错误：5 分钟
- 其他错误：5 分钟

### 工作原理

1. **问题账号缓存** (`problematicCache`)
   - 当账号出现任何异常时，会被标记为有问题
   - 5 分钟内不会被选择使用
   - 5 分钟后自动恢复

2. **限流账号缓存** (`rateLimitedCache`)
   - 专门记录 429 限流错误
   - 同样是 5 分钟后自动恢复
   - 429 错误会同时标记到两个缓存中

3. **账号选择优先级**
   - 优先选择正常账号
   - 其次选择限流账号（如果所有账号都有问题）
   - 最后选择有问题的账号（如果没有其他选择）

### 优势

1. **快速恢复**：5 分钟的限流时间确保账号能快速恢复使用
2. **统一管理**：所有异常统一处理，简化逻辑
3. **避免长时间禁用**：防止账号因临时问题被长时间禁用

### 日志示例

```
🚫 Marked account xxx as problematic (reason: http_error_429, duration: 5m0s)
🚫 Account marked as rate limited for 5 minutes: xxx
```

### 注意事项

- 这个限流机制仅在内存中维护，重启服务后会清空
- 如果某个账号频繁出现问题，建议在 Redis 中将其设置为 `isActive: false`
- 可以通过监控日志来观察账号的异常频率
